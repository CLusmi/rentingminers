Templates vast.ai pour clusmi/rentingminers
===========================================
Launch mode : Docker ENTRYPOINT  ·  champ des arguments : vide.
Remplace POOL:PORT par ta pool et les ADRESSE_... par tes wallets.
Deux façons de saisir : dans le champ « Docker Options », les lignes ci-dessous telles
quelles (avec -e et les guillemets) ; ou dans la section « Environment Variables », une
case par variable, avec la valeur SANS guillemets.

--- Pearl (GPU) + Monero (CPU, XMRig) ---

-e GPU_MINER=srbminer -e GPU_ARGS="--algorithm pearlhash --pool POOL:PORT --wallet ADRESSE_PEARL --worker FARM --pearl-k1" -e CPU_MINER=xmrig -e CPU_ARGS="--coin monero -o xmr.kryptex.network:7029 -u ADRESSE_MONERO/RENT -t 184 -k"

--- Pearl (GPU) + DragonX (CPU, SRBMiner) ---

-e GPU_MINER=srbminer -e GPU_ARGS="--algorithm pearlhash --pool POOL:PORT --wallet ADRESSE_PEARL --worker FARM --pearl-k1" -e CPU_MINER=srbminer -e CPU_ARGS="--algorithm randomdrgx --pool POOL_DRAGONX:PORT --wallet ADRESSE_DRAGONX.RENT --cpu-threads 180"

--- Pearl seul (GPU) ---

-e GPU_MINER=srbminer -e GPU_ARGS="--algorithm pearlhash --pool POOL:PORT --wallet ADRESSE_PEARL --worker FARM --pearl-k1"

--- Monero seul (CPU, XMRig) ---

-e CPU_MINER=xmrig -e CPU_ARGS="--coin monero -o xmr.kryptex.network:7029 -u ADRESSE_MONERO/RENT -t 184 -k"

Règle : un côté démarre seulement si son MINER et ses ARGS sont renseignés tous les deux.
Rien n'est prérempli : sans GPU_MINER + GPU_ARGS, pas de minage GPU ; sans CPU_MINER + CPU_ARGS,
pas de minage CPU.

--pearl-k1 : nouveau code pearlhash de SRBMiner, apparu en 3.7.2. Avec une image plus
ancienne, SRBMiner refuse l'option et ne démarre pas : d'abord l'image à jour, ensuite l'option.

Pour vérifier un template sans miner : ajoute -e DRY_RUN=1, les deux commandes complètes
s'affichent dans les logs, puis enlève-le.


SaladCloud (Pearl seul, GPU) avec chien de garde
================================================
Container group → Docker Run (ou Environment Variables, une case par variable, valeurs
SANS guillemets). Sur Salad, une machine = une carte, donc le worker est le même sur tous
les replicas ; la pool affiche leur hashrate cumulé.

--- Première mise en service : mode observe (surveille, écrit ses verdicts, n'agit pas) ---

docker run --gpus all -e GPU_MINER=srbminer -e GPU_ARGS="--algorithm pearlhash --pool POOL:PORT --wallet ADRESSE_PEARL --worker SALAD --pearl-k1" -e SALAD_WATCHDOG=observe -e SALAD_MIN_HASHRATE=5090=385T,4090=300T,3090=125T -e SALAD_GRACE=90 -e SALAD_BAD_READINGS=2 -e SALAD_MAX_RESTARTS=5 -e SALAD_ZERO_READINGS=2 -e SALAD_STALE_MINUTES=2 clusmi/rentingminers:AAAA-MM-JJ-HHMM

--- Ensuite : mode reallocate (demande à Salad une autre machine quand une règle se déclenche) ---

docker run --gpus all -e GPU_MINER=srbminer -e GPU_ARGS="--algorithm pearlhash --pool POOL:PORT --wallet ADRESSE_PEARL --worker SALAD --pearl-k1" -e SALAD_WATCHDOG=reallocate -e SALAD_MIN_HASHRATE=5090=385T,4090=300T,3090=125T -e SALAD_GRACE=90 -e SALAD_BAD_READINGS=2 -e SALAD_MAX_RESTARTS=5 -e SALAD_ZERO_READINGS=2 -e SALAD_STALE_MINUTES=2 clusmi/rentingminers:AAAA-MM-JJ-HHMM

--- Dual : Pearl (GPU) + Monero (CPU, XMRig) sur Salad ---

ajoute -e CPU_MINER=xmrig -e CPU_ARGS="--coin monero -o xmr.kryptex.network:7029 -u ADRESSE_MONERO/RENT -t 2 -k"
(sur Salad, le nombre de vCPU du groupe est petit : adapte -t au nombre de vCPU demandé)

Règles du chien de garde (actif seulement sur Salad, jamais sur vast.ai) :
- après le répit (SALAD_GRACE, en secondes) suivant chaque démarrage du mineur GPU,
  SALAD_BAD_READINGS lectures consécutives sous le seuil de la carte donnent un verdict ;
- une carte dont le modèle n'est pas dans SALAD_MIN_HASHRATE n'est pas surveillée (ligne
  « Pas de seuil pour ... » dans les logs) ; la clé 3090 couvre aussi la 3090 Ti ;
- SALAD_MAX_RESTARTS=5 : verdict si le mineur GPU redémarre 5 fois en 10 min (facultatif) ;
- SALAD_ZERO_READINGS=2 : deux lectures à 0 H/s de suite (0 = désactivé) : verdict ;
- SALAD_STALE_MINUTES=2 : plus aucune statistique pendant 2 min (0 = désactivé) : verdict ;
- après un verdict, 10 min de pause avant une nouvelle décision.
Les seuils se placent vers 85 % du hashrate réel d'une carte saine (menu 2 de
Salad-Switch-Log) : un seuil au-dessus de ce que font tes cartes réalloue toutes les
machines sans fin. Commence en observe, lis les lignes [salad] une heure, puis reallocate.
Les lignes du chien de garde commencent par [salad] dans les logs du conteneur.
AAAA-MM-JJ-HHMM = étiquette datée du build (résumé du workflow GitHub, ex. 2026-10-07-1215).
Sur Salad, toujours l'étiquette datée, jamais latest : Salad garde l'image copiée à la création
du groupe tant que l'étiquette ne change pas. Nouveau build = Edit → Image Source → nouvelle
étiquette (ou menu 3 → 1 de Salad-Switch-Log). Changer les variables ou l'étiquette redéploie
tous les replicas.
